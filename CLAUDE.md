## Project Overview

This is a multilingual medical practice website for "Praxis Jona" in Berlin, built with Next.js App Router and TypeScript. The site serves patients with information, blog content, and appointment booking integration.

## Common Development Commands

```bash
# Start development server (content-collections watches /posts inside next dev)
npm run dev

# Build for production (postbuild generates the sitemap; production builds also submit it to search engines)
npm run build

# Run linting
npm run lint

# Start production server
npm run start

# Generate sitemap manually
npm run gen-sitemap

# Run the Node and Vitest suites
npm test

# Run the Playwright suite
npm run test:e2e
```

## Architecture & Key Patterns

### Tech Stack
- **Framework**: Next.js App Router (version in `package.json`)
- **Language**: TypeScript (tsconfig strict mode disabled)
- **Styling**: Tailwind CSS with custom medical theme colors
- **Content**: MDX blog posts via content-collections
- **Email**: SendGrid API for contact forms
- **Analytics**: Vercel Analytics + Umami

### Directory Structure
- `/app` - Next.js App Router pages and components (German by default)
  - `/app/(en)/en` - English version pages (mirrors German structure)
  - `/app/components` - Shared UI components (pricing, buttons, sections)
  - `/app/api` - API routes (contact email, medical forms, analytics, and others)
  - `/app/data` - Data files (apps, jobs, doctor profile)
  - `/app/styles` - Custom CSS animations
  - `/app/(de)/leistungen`, `/app/(de)/schwerpunkte`, etc. - German service/content pages
- `/posts` - MDX blog content (processed by content-collections)
- `/public` - Static assets (images, icons)
- `.content-collections` - Auto-generated by content-collections (gitignored)

### Key Development Patterns

1. **Internationalization**: Manual i18n with `/en` routes for English content. German pages live in `app/(de)` and serve from the root URL. English pages live in `app/(en)/en`. When creating new pages, mirror the structure in both locations.

2. **Blog Posts**:
   - Create MDX files in `/posts` directory
   - content-collections automatically processes them during `npm run dev` (watch mode) or build
   - Post schema defined in `content-collections.ts` with required fields: `title`, `date`
   - Optional frontmatter: see the schema in `content-collections.ts` (for example `coverImage`, `coverImageIsAiGenerated`, `medicalReviewer`, `language`, `slugEn/slugDe`)
   - Generated fields: `slug`, `url`, `structuredData` (for SEO)

3. **Styling**:
   - Use Tailwind utilities with custom medical theme colors (primary, darkBeige, lightBeige, tealColor)
   - Custom animations in `/app/styles/animations.css` (slideInFade, zoomIn, zoomOut)
   - Additional keyframes in `tailwind.config.js` (popIn, popOut, fadeIn, fadeOut)

4. **External Integrations**:
   - **Doctolib**: Appointment booking via redirects in `next.config.js` (`/termin-buchen` → Doctolib)
   - **SendGrid**: Contact form email (`/app/api/sendgrid/route.ts`, requires `SENDGRID_API_KEY` env var)
   - **Vercel Analytics**: Analytics tracking integrated
   - **next-sitemap**: Auto-generates sitemap after build (config in `next-sitemap.config.js`)

5. **Shared Components**: Top-level components in `/app` (Contact, Footer, Header, NewsletterSection, etc.) are used across pages. Reusable UI components in `/app/components`.

## Important Configuration

- **next.config.js**:
  - Wrapped with `withContentCollections()` for MDX processing
  - Images: `unoptimized: true`, allows all remote patterns
  - Redirects: `/termin-buchen` → Doctolib, `/qr-google-review` → Google Reviews, etc.
  - Rewrites: `/impressum-datenschutz` and `/imprint-privacy` map to `/legal/*` pages

- **content-collections.ts**: Defines the `posts` collection schema and MDX processing with rehype plugins (code highlighting, autolink headings, slugs)

- **tailwind.config.js**: Custom theme with medical practice colors and custom animations

- **tsconfig.json**: Strict mode disabled (`"strict": false`), path alias `content-collections` for the generated posts

- **Environment Variables**: `SENDGRID_API_KEY` required for contact form functionality

- **Node Requirements**: Requires Node.js >= 22.0.0 (see package.json engines)

- **Tests**: Vitest and Node's test runner (`npm test`), Playwright (`npm run test:e2e`)
